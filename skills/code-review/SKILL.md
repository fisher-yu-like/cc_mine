# 代码审查技能 (Code Review Skill)

本技能规定了对代码库变更进行扫描时的标准审计流程，高度关注执行边界、资源管理以及跨平台兼容性。

## 核心审计检查点
*   **资源泄漏 (Resource Leakage)**：确保所有文件句柄、网络连接在结束时被显式关闭，或者安全地包裹在 `with` 上下文管理器中。
*   **字符编码崩溃隐患 (Encoding Errors)**：所有涉及文件读写（Read/Write）的工具，必须**显式指定** `encoding="utf-8"`，以彻底抹平 Windows 系统（默认 GBK）等跨平台运行时引发的解析崩溃。
*   **异常隔离 (Exception Isolation)**：工具的内部执行与外部 API 调用必须包裹在局部 `try-except` 块中，并将精准的错误信息向上浮动（Bubble Up）。

## 自动化审查输出格式化器
当被要求进行代码审查时，务必将发现的问题组织成如下的 Markdown 表格布局：

| 文件与行号 | 严重等级 | 核心问题描述 | 推荐的惯用修复方案 |
| :--- | :--- | :--- | :--- |
| `path/to/file.py:45` | 高危 (High) | `open()` 函数缺少 `encoding="utf-8"` 参数 | 添加该参数以确保在 Windows 宿主机上运行不会因 GBK 报错。 |
| `path/to/file.py:89` | 中危 (Medium) | `while` 循环未设置安全边界或超时时间 | 实现一个最大迭代次数计数器（Threshold）以强制阻断死循环。 |

## 重构标准
拒绝提出任何纯视觉、纯修辞层面的样式修改建议。审查意见必须百分之百聚焦于代码的正确性、数据解析安全性以及性能退化（Regressions）上。
